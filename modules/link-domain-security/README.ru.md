# Модуль "Безопасность ссылок и доменов"

## Назначение
Анализирует ссылки, домены, redirect-паттерны, гомографические сигналы и небезопасные протоколы навигации.

## Архитектура
- `LinkDomainSecurityDetector.js` остаётся точкой входа и orchestrator-файлом модуля.
- `detectors/hostnameSecurityDetector.js` содержит stub-анализ текущего hostname и target-hostname.
- `detectors/navigationTargetDetector.js` содержит stub-анализ unsafe protocol, redirect-pattern и `<base href>` сценариев.
- `detectors/visibleMismatchDetector.js` содержит stub-анализ несовпадения видимого текста ссылки и реального target.
- `utils/urlUtils.js` хранит helper'ы для парсинга URL и redirect-query параметров.
- `utils/domainUtils.js` хранит helper'ы для hostname, protocol и mismatch-проверок.
- `utils/findingFactory.js` хранит helper'ы для единого формата findings.

## Текущий статус
- Эвристическая заглушка уровня MVP.
- Модуль подключён к runtime и формирует пассивные findings.
- Модуль ничего не блокирует. При открытом гейте вмешательства он отдаёт узел находки `link-mismatch`, и метку рядом со ссылкой ставит слой, а не модуль.

## Ключи конфигурации
- `enabled`
- `detectHomographs`
- `detectLinkMismatch`
- `detectRedirectPatterns`
- `detectUnsafeProtocols`
- `sensitivity`
- `actionOnDetect`

## Текущее поведение
- Проверяет текущий hostname на punycode, mixed-script и whole-script confusable сигналы. Лейбл,
  целиком написанный не-латинским шрифтом, у которого каждая буква имеет латинского двойника, — это
  каноническая гомографическая подделка; она сообщается как `hostname-confusable`. Имя, записанное письменностью собственной IDN-зоны (`сахар.рф`), подделкой не считается, а лейблы короче четырёх букв не рассматриваются вовсе. Так же сообщается имя из обычных букв с одной подменённой, которой ни один язык доменные имена не пишет (блоки IPA и латинских капителей, как в `gogleɟ.com`): правила разные, фраза для пользователя одна. Буквы реальных орфографий (`ü`, `ı`, `ł`, `ø`, `ß`) подменой никогда не считаются; простая запись о punycode выдаётся только там, где письменность имени не принадлежит зоне, а в ASCII-зоне выдаётся всегда — там это единственный сигнал, способный увидеть подделку, написанную необычными латинскими буквами; смешением скриптов считается сочетание любых двух из латиницы, кириллицы и греческого внутри одного лейбла. Легитимные IDN
  при этом не эскалируются.
- Анализирует цели `a[href]`, `form[action]` и `formaction` у submit-контролов. `formaction` перекрывает
  собственный `action` формы, поэтому безобидная на вид форма может отправлять данные куда угодно;
  цель проверяется теми же правилами, а видимого текста такой кандидат не даёт (подпись кнопки
  живёт в атрибуте `value`, читать который нельзя).
- Разрешает относительные цели относительно `document.baseURI`, поэтому `<base href>` не может
  подменить адреса, которые анализирует модуль. `<base href>` на чужой origin сам по себе сообщается
  как `base-origin-mismatch`: он перенаправляет разом все относительные ссылки страницы.
- Выявляет небезопасные протоколы (`javascript:`, `vbscript:`, `data:`, `file:`) и типовые redirect-query параметры. Назначение редиректа, которое
  не разбирается как URL, но по форме им является (голый хост, base64-payload, дважды закодированный
  URL), сообщается с низкой severity; короткие значения-идентификаторы игнорируются. Порог длины
  применяется только к encoded- и base64-формам: голый хост судится собственным guard'ом, поэтому
  `?url=evil.com` не пропускается из-за короткой длины.
- Фиксирует несовпадения видимого текста ссылки и реального target. Видимый текст считается
  hostname'ом только если последний лейбл — известная зона и не расширение файла, поэтому имена
  файлов, даты, цены и точечные идентификаторы кода (`Object.keys`, `os.path`) в подписи ссылки
  несовпадением не считаются. Сравниваются **все** хосты, названные в подписи, а не только подпись,
  целиком состоящая из хоста, поэтому «Войти на paypal.com» проверяется; совпадение любого из
  названных хостов с целью снимает подозрение.
  Известный предел: подпись называет бренд, а файл лежит на CDN под другим registrable-доменом —
  это читается как несовпадение. Оффлайн отличить такое от настоящего нечем (Public Suffix List в
  модуле нет); CDN на поддомене того же домена молчит.
- Findings опознаются по содержанию, а не по узлу: повторный рендер тех же ссылок не сообщается
  заново. Ключи живут в пределах скана и вытесняются по FIFO при переполнении.
- Candidate collection выполняется итеративно и с budgets; модуль не материализует page-wide или added-subtree результат `querySelectorAll()`.

## Runtime и производительность
- Automatic continuous monitoring работает только в foreground-вкладке сфокусированного окна Chrome и только в main frame. Одна только инъекция content script не активирует модуль.
- Явный scan paused/background-вкладки является bounded one-shot. При pause/destroy удаляются observer, timer, pending roots, scan-local ссылки на элементы и хранящиеся внутри модуля finding details.
- Initial profile: 20 000 посещённых DOM-элементов, 3 000 target candidates и 100 ms elapsed time.
- Mutation profile: минимальный интервал 500 ms, 200 входящих records, 100 added nodes на record, 1 000 added nodes на callback, 100 coalesced roots, 1 000 посещённых DOM-элементов, 300 candidates и 25 ms elapsed time.
- Raw `href`/`action` длиннее 8 192 символов пропускается и помечает snapshot как partial. Visible link text читает не более 64 nodes и 2 048 символов, исключая form controls и editable surfaces.
- Overflow отбрасывается и отражается в bounded counters и `partialResult`; detector не создаёт неограниченную catch-up очередь.

## Session snapshot
- При pause последний snapshot сериализуется до cleanup модуля, но отправляется только после остановки detector pipeline.
- В `chrome.storage.session` сохраняются counts, не более 10 normalized findings, revision, timestamp и partial/stale state.
- Cached link findings содержат только `type`, локализованный `summary`, `severity` и `detector`. URL, hostname, `href`, `action`, visible link text, form values, finding details и DOM references не сохраняются.
- Общая cache schema версионирована. Navigation и значимые config changes инвалидируют snapshot без пробуждения background tabs.

## Интеграция с индикатором страницы
- Findings этого модуля должны участвовать в общем page-level индикаторе расширения.
- Каждая найденная проблема увеличивает общий счётчик action icon на 1.
- Если на странице есть хотя бы одна проблема, иконка расширения должна становиться красной и показывать badge с числом проблем.
- Если findings на странице нет, иконка должна показывать классическую зелёную галочку.

## Архитектурные ограничения
- `LinkDomainSecurityDetector` должен оставаться публичной точкой входа модуля.
- Не нужно дробить модуль до одного файла на каждую микро-эвристику.
- Сетевые проверки доменов, DNS, reputation lookup и blacklist API не входят в MVP-объём.
- Активная блокировка ссылок и DOM-вмешательство здесь не добавляются без отдельного согласования.

## Примечание
Модуль остаётся пассивным: по находке `link-mismatch` он отдаёт `emitFindingNode(finding, node)` и сам в страницу не пишет. При открытом гейте слой ставит метку РЯДОМ со ссылкой, а не внутрь неё: метка внутри `<a>` стала бы частью той самой видимой подписи, которую детектор сравнивает с адресом. Активное вмешательство закрыто гейтом `settings.activeRemediationEnabled` (по умолчанию выключен) и применяется слоем `js/intervention-layer.js`.

Real-Chrome acceptance с 50+ восстановленными вкладками, несколькими окнами, быстрым переключением и sustained SPA mutations остаётся обязательной ручной проверкой.
